# 안드로이드 제스처 스파이크 결과

작성일: 2026-08-26 / 위치: `android/` (브랜치 `android-spike`) / 검증 환경: 에뮬레이터 API 36

`docs/android-handoff.md` 7장에서 최대 기술 리스크로 꼽은 "Compose에서 제스처 5종 공존"을 더미 데이터로 검증했다.

## 결론: Compose로 간다. 라이브러리 없이 자체 구현으로 충분하다.

| 제스처 | 결과 |
|---|---|
| 왼쪽 스와이프 완료 (0.3초 슬라이드아웃 + 그라데이션) | 동작 |
| 더블탭 중요 표시 (테마색 테두리) | 동작 |
| 길게 누르기 → 다이얼로그 (수정/삭제/고정/선택) | 동작 |
| 길게 누른 뒤 드래그 → 섹션 내 순서 변경 | 동작 |
| 드래그로 다른 날짜 섹션 이동 (date 변경) | 동작 |
| 고정/고정 해제, 고정 바 접기/펼치기, 오늘 자동 스크롤 | 동작 |

reorder 라이브러리 없이 `detectDragGesturesAfterLongPress` + `LazyListState.layoutInfo` 기반 자체 구현(~60줄)으로 해결됐다.

## 본 구현에 반드시 가져가야 할 함정 3개

1. **드래그 감지기는 셀(안쪽)에 걸어야 한다. 리스트(바깥)에 걸면 안 된다.**
   Compose 포인터 디스패치는 안쪽 핸들러가 먼저 소비한다. `LazyColumn`의 modifier에 감지기를 걸면 리스트 내부 스크롤(더 안쪽)이 세로 이동을 먼저 소비해서 드래그가 즉시 취소된다. 셀에 걸면 셀이 먼저 소비해 스크롤을 이긴다.

2. **길게 누르기 후 릴리즈 시 `onDragEnd`가 아니라 `onDragCancel`이 올 수 있다.**
   같은 셀의 `detectTapGestures`(더블탭용)가 UP 이벤트를 소비하면 드래그 감지기는 cancel로 끝난다. "이동량 없으면 다이얼로그" 처리를 end/cancel 양쪽에 동일하게 넣어야 한다. 이동량 판정은 touchSlop 기준.

3. **레이아웃 측정 전 `scrollToItem`은 오버스크롤된 채 멈출 수 있다.**
   앱 실행 직후 오늘 섹션 자동 스크롤 시 첫 프레임이 빈 화면이 될 수 있다. `scrollToItem` → `withFrameNanos {}` → `scrollToItem` 재호출로 보정했다. 본 구현에서는 유사 처리 필수.

## 구현 방식 요약 (본 구현 시 참고)

- 데이터: flat `List<SpikeTodo>` + `groupBy(date)`로 섹션 파생. 드래그로 다른 섹션 위에 놓이는 순간 항목의 date를 대상 섹션으로 즉시 변경 (iOS는 드롭 시점 변경이지만 결과 동일, 구현 단순).
- 이동 보정: 항목 교환 시 `offsetY ±= target.size`, 헤더 통과 시 `offsetY ±= header.size` (방향에 따라 부호 반전).
- 헤더 통과 규칙: 아래로 넘으면 해당 섹션 첫 번째, 위로 넘으면 이전 섹션 마지막.
- 드래그 중인 셀: `zIndex(1f)` + `graphicsLayer { translationY }` + `shadowElevation`, 나머지 셀은 `animateItem()`.
- 스와이프/더블탭/드래그 감지기는 셀에 각각 별도 `pointerInput`으로 공존 (충돌 없음).
- 완료/삭제는 전부 **id 기준** 조회 — handoff 4장 8번(stale index) 함정이 구조적으로 발생하지 않음.

## 스파이크에서 안 한 것 (본 구현 과제)

- 드래그 중 화면 가장자리 자동 스크롤 (긴 리스트에서 필요)
- 드래그 프리뷰 디테일 (iOS는 "말풍선만 들어올림")
- 스와이프 임계값/속도 튜닝, 연속 스와이프 스트레스 테스트
- 실기기 검증 (에뮬레이터만 확인)
