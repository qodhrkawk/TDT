# Flick 안드로이드 버전 Handoff 문서

작성일: 2026-08-26 / 기준 버전: iOS 3.0.0 (main `dc7fb70`, App Store 심사 제출 상태)

이 문서는 iOS 코드를 열어보지 않고도 Flick 안드로이드 버전을 개발할 수 있도록 제품 컨셉, 기능 스펙, 데이터 모델, 암묵적 비즈니스 규칙, 디자인 값을 정리한 것이다. 각 항목에 iOS 원본 파일 경로를 근거로 달아두었으니 애매하면 해당 파일을 확인한다.

---

## 1. 제품 컨셉

> 우리가 해야 하는 일들이 모두 오늘 시작해서 오늘 끝내야만 하는 게 아니니까, 플릭엔 달력 뷰도 데드라인 설정도 없어요. 잊어버리면 안 될 일들만 플릭이 대신 기억할게요.

- **데드라인 없음, 달력 없음, 알림 없음.** 날짜는 "적은 날"의 기록일 뿐 마감이 아니다.
- 핵심 루프: 기록하기 → (미루기) → 완료하기(스와이프) → 아카이브에 쌓임.
- 서버 없음. 100% 로컬 데이터. 로그인/계정 없음. (3.1에서 Flick Pro 유료화 계획이 있으나 안드로이드 1.0 범위 아님 — `docs/3.0-improvement-plan.md` 참고)
- 3.0은 앱스토어 리뷰 50개 분석 기반으로 최다 요청 기능 3종(순서 변경·고정·일괄 선택)과 최다 신고 버그(위젯 고착, 스와이프 오삭제)를 반영한 버전이다. 안드로이드는 이 3.0 스펙을 기준으로 만든다.

## 2. 화면 구성

화면은 딱 3개 + 페이지 스와이프 전환이다.

### 2.1 메인 (할 일 리스트)

- 헤더: Flick 로고(탭 → 설정), 아카이브 버튼.
- **고정(pin) 스티키 바**: 리스트 위에 항상 떠 있음. "고정됨 N" 헤더 탭으로 접기/펼치기(상태 저장). 최근 고정이 맨 위.
- 리스트: **날짜별 섹션, 과거 → 오늘 순** (오늘이 맨 아래). 섹션 내 순서는 입력순이며 드래그로 변경 가능.
- 하단 입력창: 텍스트 1자 이상이면 전송 버튼이 테마색으로 활성화. 추가는 항상 오늘 날짜 섹션으로.
- **앱 실행 시 오늘 섹션으로 자동 스크롤** (고정 바 + 오늘 할 일이 첫 화면에 보여야 함).
- 화면을 옆으로 스와이프하면 아카이브 화면으로 전환 (ViewPager 형태).

셀 제스처 (선택 모드가 아닐 때):

| 제스처 | 동작 |
|---|---|
| 왼쪽 스와이프 | 완료 → **오늘 날짜**로 아카이브 이동. 0.3초 슬라이드아웃 + 그라데이션 |
| 더블탭 | 중요 표시 토글 (셀에 테마색 1.5px 테두리) |
| 길게 누르기 | 다이얼로그: 수정 / 삭제 / 고정(또는 고정 해제) / 선택 |
| 길게 누른 뒤 드래그 | 순서 변경. **다른 날짜 섹션으로 옮기면 항목의 date가 그 섹션 날짜로 변경**. 드래그 프리뷰는 말풍선만 들어올림 |

일괄 선택 모드 (다이얼로그의 "선택"으로 진입):

- 진입한 항목은 체크된 상태로 시작. 이후 행 전체 탭으로 체크/해제 (더블탭 대기 없음).
- 하단 입력창이 "취소 | 완료 N | 삭제 N" 바로 교체됨.
- 일괄 완료 → 전부 오늘 날짜로 아카이브. 일괄 삭제 → 확인 알럿 1회 후 삭제.
- 모드 중 스와이프/드래그/더블탭 전부 비활성.

### 2.2 아카이브

- 날짜별 섹션, **최신순** (오늘이 맨 위).
- 왼쪽 스와이프: 항목을 **원래 날짜**로 메인에 복원 (해당 날짜 섹션이 없으면 날짜순 위치에 새로 생성).
- 더블탭: 중요 표시 토글. 길게 누르기: 수정/삭제.
- 진입 시 헤더·셀이 오른쪽에서 슬라이드인 (섹션별 +0.05초, 행별 +0.02초 지연).

### 2.3 설정

| 섹션 | 내용 |
|---|---|
| 화면 스타일 | 시스템 / 라이트 / 다크 (강제 모드, 위젯에도 적용) |
| 테마 색상 | 7종 (아래 6장). 선택 즉시 앱·위젯 반영 |
| 1:1 문의하기 | 메일. 안드로이드는 `ACTION_SENDTO`(mailto) → 처리 앱 없으면 주소 복사 안내의 2단계 폴백이면 충분 |

### 2.4 첫 실행

`initiated` 플래그가 없으면 가이드용 할 일 3개를 오늘 날짜로 자동 추가하고 플래그 저장 (일회성). 문구는 iOS와 통일 (TodoViewController 참고).

## 3. 데이터 모델

원본: `TDT/TDT/Data/TodoData.swift`, `TodoStore.swift`

```kotlin
data class TodoData(
    val date: String,        // "yyyy.MM.dd" (예: "2026.08.26") — 기기 로컬 시간
    val todo: String,        // 본문. 길이 무제한, 줄바꿈 허용
    val isImportant: Boolean,
    val isPinned: Boolean = false,
)
```

저장 상태는 5덩어리다:

| 이름 | 타입 | 설명 |
|---|---|---|
| `todoDatas` | `List<List<TodoData>>` | 날짜별 섹션. 섹션은 날짜 문자열 오름차순, 섹션 내부는 사용자 순서 |
| `dateInfo` | `List<String>` | 각 섹션의 날짜. **todoDatas와 길이가 항상 일치해야 함** (로드 시 불일치면 재계산) |
| `pinnedDatas` | `List<TodoData>` | 고정 항목 전역 배열. 최근 고정이 앞. 각 항목의 date는 원래 날짜를 유지 |
| `archiveDatas` + `archiveDates` | 위와 동일 구조 | 완료 항목. 섹션은 최신순 (새 날짜는 맨 앞에 삽입) |
| 설정 | theme(Int 0–6), trait(system/light/dark), initiated, pinnedBarCollapsed(Bool) | |

- 날짜 비교는 전부 **"yyyy.MM.dd" 문자열 사전순 비교**로 동작한다 (zero-pad라 사전순 = 시간순). 안드로이드도 동일 포맷을 쓰면 로직을 그대로 옮길 수 있다.
- iOS는 할 일 데이터를 PropertyList, 설정을 JSON으로 저장하지만 이는 레거시다. **안드로이드는 전부 JSON(kotlinx.serialization) + DataStore(또는 Room)로 통일**하면 된다. iOS와의 데이터 교환은 없으므로 바이너리 호환은 불필요.
- 위젯과 데이터를 공유해야 하므로 저장소는 위젯 프로세스에서도 읽을 수 있는 위치에 둔다 (SharedPreferences/DataStore면 충분 — 안드로이드 위젯은 같은 프로세스라 iOS의 앱 그룹 문제가 없다).

## 4. 핵심 비즈니스 규칙 (코드에만 있는 암묵적 규칙)

원본: `TDT/TDT/Data/TodoStore.swift` — **가장 중요한 파일.** 이 로직에 대한 유닛 테스트 19개가 `TDT/Tests/TodoStoreTests.swift`에 있으니 안드로이드에서도 같은 케이스로 테스트를 옮기는 것을 권장.

1. **추가**: 항상 오늘 섹션에 append. 오늘 섹션이 없으면 맨 뒤에 생성.
2. **완료(아카이브)**: 완료한 항목은 **완료 시점의 오늘 날짜**로 아카이브에 들어간다 (원래 적은 날짜가 아님). 고정 상태였다면 `isPinned = false`로 해제 후 이동.
3. **복원**: 아카이브에서 스와이프하면 항목의 **원래 date**로 메인에 돌아간다. 해당 날짜 섹션이 없으면 날짜 오름차순 위치에 새 섹션을 만들어 삽입 (`insertIntoDateSections`).
4. **고정**: 날짜 섹션에서 제거 → `pinnedDatas` 맨 앞에 삽입. date 필드는 유지(표시만 안 함). **고정 해제**: 원래 date로 3번과 동일하게 복귀.
5. **드래그 이동**: 다른 날짜 섹션에 드롭하면 항목의 date를 대상 섹션 날짜로 변경.
6. **빈 섹션 정리**: 삭제/이동/고정으로 섹션이 비면 섹션과 dateInfo 항목을 함께 제거. 모든 변경 후 실행.
7. **일괄 처리**: 인덱스를 정렬한 뒤 **역순으로 제거**해야 인덱스 밀림이 없다. 일괄 완료도 각 항목 고정 해제 후 오늘 날짜로 아카이브.
8. **리스트 변경 중 제스처**: 스와이프 완료 시점에 셀에 저장해둔 위치가 아니라 **그 순간의 실제 어댑터 위치를 재조회**해서 삭제할 것. (iOS 3.0에서 잡은 P0 버그 — 연속 스와이프 시 stale index로 엉뚱한 항목이 지워졌음. RecyclerView도 `getBindingAdapterPosition()`으로 동일 함정 주의.)

## 5. 위젯

원본: `TDT/FlickWidget/`, `TDT/FlickTodayWidget/`, `TDT/TDT/Helpers/WidgetDataManager.swift`

### 5.1 종류와 내용

| 위젯 | 내용 |
|---|---|
| 홈 (중형/대형) | 고정 항목 우선 + 최근 항목. 중형 5줄, 대형 10줄, 전체 최대 10개 |
| 오늘 (중형/대형) | 오늘 날짜 항목만, 중형 5 / 대형 10 |
| (iOS 잠금화면 위젯) | 최근 3개 — 안드로이드는 해당 없음, 스킵 |

위젯용 데이터 구성 규칙: `capacity = 10 - 고정 개수`, 비고정 항목을 최근 것부터 capacity만큼 취해 원래 순서로 뒤집은 뒤 `고정 + 최근` 순으로 이어붙이고 10개로 자른다.

### 5.2 갱신 정책

- 데이터가 바뀔 때마다 앱이 위젯용 데이터 저장 + 위젯 갱신 트리거 (안드로이드: `AppWidgetManager.updateAppWidget` / Glance `updateAll`).
- iOS는 재부팅 직후 위젯이 저장소를 못 읽어 "할 일을 모두 완료했어요!"로 고착되는 P0 버그가 있었고, "읽기 실패 시 캐시 유지 + 15분 뒤 재시도"로 해결했다. 안드로이드는 Direct Boot 상태가 아니면 이 문제가 거의 없지만, **읽기 실패 시 빈 상태로 덮어쓰지 말고 이전 상태를 유지**하는 원칙은 동일하게 지킬 것.
- 위젯도 앱의 화면 스타일 설정(라이트/다크 강제)을 따라야 한다. iOS에서는 배경색을 강제 스타일로 미리 resolve한 고정 색으로 넘겨 해결했다 (`View+WidgetBackground.swift`). 안드로이드도 위젯 렌더링 시 시스템 다크모드가 아니라 **앱 설정값 기준으로 색을 선택**한다.
- 빈 상태 문구: "할 일을 모두 완료했어요!"

### 6.3 폰트·셀·모션

- 폰트: **Gmarket Sans Medium** (TTF 동봉 필요, 무료 라이선스). 셀/입력 15sp, 고정 라벨 14sp, 헤더 부제 12sp.
- 셀(말풍선): 텍스트 패딩 상하 15 / 좌우 18, cornerRadius 8. 중요 표시는 테마색 1.5 테두리, 우상단 핀 아이콘 14×14.
- 스와이프 완료: 0.3초에 화면 밖으로 슬라이드아웃 + 우측 그라데이션 페이드인. 이 "빠릿함"이 앱의 핵심 감각이므로 반드시 재현할 것 (2.x는 ~1초였고 최다 불만이었음).
- 진입 모션: 셀들이 오른쪽에서 왼쪽으로 순차 슬라이드인 (섹션 +0.05초, 행 +0.02초 지연).
- **UI에 시스템 이모지 사용 금지.** 아이콘은 벡터 드로어블로.

## 7. 안드로이드 기술 스택 권장

강제는 아니고 제안:

- Kotlin + Jetpack Compose, 단일 모듈로 시작 (앱 규모가 작다).
- 데이터: kotlinx.serialization + DataStore(Preferences 또는 Proto). Room은 과함.
- 위젯: Glance (홈 중형/대형 + 오늘 위젯 2종).
- 드래그 정렬: Compose `LazyColumn` + reorder 라이브러리 또는 자체 구현. 섹션 간 이동(date 변경)까지 되는지 먼저 검증할 것 — **기술 리스크가 가장 큰 부분**.
- 최소 SDK: 26+ 권장 (위젯·다크모드 처리 단순화).
- TodoStore에 해당하는 순수 Kotlin 저장소 클래스를 먼저 만들고 4장의 규칙을 유닛 테스트로 옮긴 뒤 UI를 얹는 순서를 권장 (iOS도 같은 구조: 스토어 + 테스트 19개).
